How It Works
Scripts are generated live from Notion data — not filled in manually
Click Forecast Readout on any Team Overview card in the SLT Dashboard. The readout is built from the current Notion sync: forecast dates, statuses, blockers, Confidence, milestone progress, owner goals, and historical snapshots. Copy the output and use it to guide the forecast call.

Source fields: Notion PSA Onboarding Clients (PSA) · Notion Billing Onboarding Clients (Billing) · Owner Goals on the Forecast database · forecast history snapshots for committed baselines.

Proposed Forecast Call Flow
Recommendation
Use one short spoken flow and keep movement detail in the dashboard
The proposed change is not to review forecast movement or per-project forecast detail in the copied/read-aloud portion. The dashboard should keep the snapshots, movement deltas, and underlying project evidence. The spoken readout should be a short metric summary, followed by one prompt to discuss key risks, active blockers, product blockers, or leadership help if needed.
Section 1 New Spoken Flow Template

This is the proposed structure for the copied/read-aloud forecast script. Variables are shown as field names so leadership can review the flow without getting caught in placeholder math.

[Owner Name] - [Line of Business] Forecast Readout My commitment for [Month] is [Commit Count] projects for [Commit MRR] MRR. My current most likely is [Most Likely Count] projects for [Most Likely MRR] MRR. Delta versus commit is [Delta Count] projects for [Delta MRR] MRR. Worst case is [Worst Count] projects for [Worst MRR] MRR. Best case is [Best Count] projects for [Best MRR] MRR. I have [Graduated or Activated Count] this month for [Actualized MRR] MRR. Be ready to discuss key project risks, active blockers, product blockers, and any help needed from leadership.
Important wording cleanup
PSA should use one graduation readout. Billing should use this same structure twice: Phase 1 activations using recognized MRR, and Phase 2 graduations using total MRR context. Do not blend Phase 2 completions into the Phase 1 activation commitment.

Logic PSA Confidence — How It's Determined

The Confidence shown in the script is not always the raw Notion field value. The script applies an auto-inference rule when the field is blank:

Auto-Inference Rule
If Confidence field is blank AND no blocker is set → treated as High
If Confidence field is blank AND a blocker exists → treated as Medium
If Confidence field has an explicit value → that value is used as-is

This means a client can appear as High Confidence without the field being explicitly set — it is inferred from the absence of a blocker. To override, set the Confidence field explicitly in Notion.

Scenario BucketPSA Confidence IncludedMeaning
Worst Case High Firmest commitments only — no blocker, or blocker is explicitly resolved
Most Likely High Medium Primary forecast number — realistic range
Best Case High Medium Low All non-canceled clients in the month — ceiling, not a commit
Logic Milestone Progress — How It's Shown

Milestone progress remains available in the dashboard for follow-up questions, but it is no longer part of the default spoken readout. If a risk or blocker needs discussion, use the milestone snapshot to support that conversation. The required figure covers critical-path milestones; overall covers all milestones.

Milestone completion contributes to the milestone progress percentage shown on the dashboard. The scoring weights each milestone by status:

Milestone Scoring
Completed = 1.0 point — full credit
In Progress = ⅓ point — partial credit
All other statuses (Not Started, On Hold, Blocked, Deferred) = 0 points

Keeping milestone statuses current in Notion directly affects the progress percentage shown in scripts and on the dashboard. An In Progress milestone is worth one-third of a Completed one.

§ 2 Discussion Prompt

The generated readout should not list every project by default. It should end with one instruction to be ready to discuss key risks, active blockers, product blockers, and any leadership help needed.

Prompt AreaMeaning
Key risksAnything likely to change the forecast date or confidence.
Active blockersAny blocker that needs ownership, due date, escalation, or a keep/remove decision.
Product blockersProduct, catalog, package, integration, API, functionality, template, or engineering issues affecting delivery.
Leadership helpAny decision, escalation, or unblock request that cannot be handled by the owner alone.
Be ready to discuss key project risks, active blockers, product blockers, and any help needed from leadership.
Billing Forecast Script
Two Readouts — Activation and Graduation
Key Difference vs PSA
Billing separates activation from graduation
PSA forecast discussions center on graduation. Billing forecast discussions have two tracks: Phase One activation and Phase Two graduation/completion. Phase One activation is the revenue-recognition event for Billing MRR. Billing graduation is later completion hygiene and should not be blended into the same forecast count as activation.

The readout should repeat the same concise metric format for each track: commitment, current most likely, delta versus commit, worst case, best case, actualized this month, and the risk/product/leadership prompt.

Billing scripts are available to PMs and SAs only. DEs are excluded.
Logic Billing Confidence — Scenario Bucket Rules
ScenarioConfidence Values IncludedBlank ConfidencePurpose
Worst Case High Excluded Floor / must-land number
Most Likely High Medium Excluded Primary forecast call number
Best Case High Medium Low Included — treated as Low Ceiling / capacity planning only
⚠️
Until Billing Confidence is populated for all active clients, scenario buckets are directional only. Clients without a Confidence value appear in Best Case only — not in Worst Case or Most Likely. Missing Confidence should be handled through the final risk/blocker discussion prompt.
Logic Activation vs Graduation Track

Billing clients follow one of two tracks, determined automatically:

Track Determination
If no Activation Date exists → Phase One Activation track — uses Current Forecast Date / forecast activation date
If the client has an Activation Date set → Phase Two Graduation track — uses Current Graduation Date for completion/graduation

The script separates these into different readouts. Activation is the primary Billing forecast number tied to MRR recognition. Graduation/completion is a separate Phase Two readout and should not inflate the Phase One activation commitment.

§ 3 Discussion Prompt

Billing ends with the same single prompt as PSA: be ready to discuss key project risks, active blockers, product blockers, and any help needed from leadership. Product blockers should be specifically called out when the blocker text points to product, catalog, package, configuration, integration, API, functionality, template, or engineering work.

Guide Facilitator Prompts

Use these only when the owner has risks, blockers, product blockers, or leadership asks to discuss after the metric readout:

  • "Any blocker?"
  • "Who owns it?"
  • "By what date does it need to clear?"
  • "Does it threaten the forecast date?"
  • "Is this forecast date real or a placeholder?"
  • "Is the Confidence field accurate?"
  • "Is this a product blocker?"
  • "Does Product or Engineering own the next action?"
  • "Does Sales need to re-engage?"
  • "Stay active, RTS, or pre-cancel?"
  • "Is the last interaction logged?"
  • "Is Confidence populated in Notion?" (Billing)
  • "Are we discussing Billing activation or Billing graduation?"
  • "Does this affect recognized MRR or only completion follow-through?"
Close Post-Call Closeout Checklist

Before the next sync, confirm these are updated in Notion:

  • Forecast date changes captured for any clients that moved
  • RTS / On Hold / pre-cancel decisions reflected in status
  • Blockers updated with owner and due date
  • Confidence field set for any clients where it was discussed
  • Billing Confidence populated for any missing clients discussed during the prompt
  • Billing activation forecast separated from Billing graduation/completion forecast
  • Month-end placeholder dates replaced with real dates or marked Low confidence
  • Product blockers routed to the right Product or Engineering owner
  • Client interactions logged for any stale accounts discussed during the prompt
  • Milestone statuses updated so progress reflects actual state

Reading the PSA Example
What to notice
1Commitment anchors the readout

The first line states the month commitment in count and MRR. It is the comparison point for the rest of the readout.

2Current most likely is the operating number

The current most likely line includes actual graduations plus the remaining most-likely forecast.

3Delta is simple

The delta line states count and MRR movement against commitment. It does not explain every moved client.

4Worst and best set the range

Worst and best case provide the floor and ceiling without adding project-by-project narration.

5Actualized this month is separate

Graduated this month is stated explicitly so completed work is included in the readout instead of disappearing from forecast.

PromptRisks come only when needed

The final prompt tells the facilitator what to ask about: key risks, active blockers, product blockers, and leadership help.
